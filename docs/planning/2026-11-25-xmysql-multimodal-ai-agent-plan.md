# XMySQL 统一存储与多模态 SQL 内核建设计划说明

版本 0.8  通用数据库架构评审稿  2026 年 11 月 25 日

2026-11-26 实施增量：在数据库 CONTENT 目录内建立带校验和及不可变代际的持久维护队列；租约支持 fencing、过期重领、续租、退避、终止失败和重启恢复。SQL DML 记录文本 CONTENT 来源主键、版本、摘要及分块处理器配置到事务 journal，并在物理提交后幂等入队；回滚不入队，已提交 journal 的恢复路径可重放入队意图；无法构造稳定来源身份时客户端提交失败关闭。普通提交/回滚、来源绑定、journal 往返、恢复重放与队列并发原语有定向测试。另修正错误结果元数据兼容：MySQL 8.4.13 的 50 条 SQL × 文本/预处理协议共 100 项差分通过，针对 1242/21000 标量运行期错误和 1267/HY000 排序规则语义错误严格比较元数据存在性。`go build -mod=readonly ./server/...` 与 `go vet -mod=readonly ./server/innodb/content ./server/innodb/engine ./server/net` 通过；新增队列事务用例、完整 `server/net` 包回归通过，完整 engine 回归尚未在本次队列接线后重跑。该段记录的是后台 worker 接入前的状态；后续实现及当前未完成范围见紧随其后的更新。

本计划的目标是一套存储、一套 SQL：在 XMySQL 现有关系模型、事务、索引、优化器和 MySQL 兼容访问方式上，统一处理结构化记录、文档、图片、音频、视频及其派生内容。开发者使用普通 Java 和 Python 数据库客户端完成导入、读取、检索和模型上下文获取，由数据库管理派生数据维护及一致性。开发分支优先保留当前 MySQL 兼容能力，新增功能采用增量扩展，并以既有能力无新增回归为发布门槛。

2026-11-26 后续实施：文本分块维护已从“提交后只入队”推进为数据库内后台处理闭环。引擎启动恢复完成且进入 READY 后启动 worker，关闭时取消并等待 worker 退出；worker 按租约读取当前聚簇行，逐块校验源版本，流式写入不可变 CONTENT 对象，再由队列以结果摘要和 fencing lease 发布 READY。结果清单引用分块流，对象回收将 READY 清单纳入 live set；`CONTENT_TEXT_CHUNKS` 可复用已发布块，`CONTENT_MAINTENANCE_STATUS(content_column[, chunk_options])` 可查询当前行版本对应的 QUEUED/LEASED/READY/FAILED 状态。过时来源失败关闭，瞬时错误退避重试，结果上限 16 MiB。内容包全量测试、维护 worker/SQL/生命周期定向 engine 测试、服务构建与 content/engine vet 通过；本次完整 engine 回归通过（392.941 秒）。该切片只处理显式文本 MIME 和内置文本分块器；没有 SQL 管理重试/保留、队列复制、Embedding 维护、多模态解析 worker、ANN/混合检索或 RAG 闭环，U05 及整体计划仍未完成。

## 实施状态（2026-11-25）

当前分支已先实现一轮 MySQL 查询兼容修复，并记录了范围内验收结果，见[查询兼容性阶段验收记录](../compatibility/2026-11-25-query-compatibility-acceptance.md)。AI/多模态工作仍是尚未端到端验证的内核原型：已新增 `server/innodb/content` 规范内容值与内容块编码，`CONTENT`/`VECTOR(n)` 类型路径、来源绑定与核验函数、跨表 DML 派生失效、受限 `CONTENT_SLICE`、`CONTENT_TEXT`、`FULLTEXT_SCORE`，以及数据库目录内的不可变分段对象存储原型 `content.SegmentStore`。新增 SQL 函数 `CONTENT_TEXT_BLOCK(content, ordinal, byte_offset, byte_length)` 可从显式文本 MIME 的 CONTENT 列读取有界 UTF-8 字节范围，并返回带当前行主键、来源修订、摘要及原件字节定位的已绑定 CONTENT 块；单次范围最多 4 MiB，调用方或后续维护任务仍需选择分块范围。该函数已通过服务代码构建，尚未经过 SQL 行为和来源失效测试，不能视为自动分块或文档解析器。`SegmentStore.NewWriter` 和预处理长参数路径现可对被识别为 `CONTENT_FROM_BYTES(?, '<literal MIME>')` 的参数逐包分段写入，避免服务端先缓存整份长参数；其他长参数仍使用既有缓冲路径。未执行语句的 writer 在 reset、close 和连接关闭时会尝试中止；执行时只把被 DML 行实际采纳的对象交给事务跟踪，其他对象由协议层清理。长参数协议保持 `COM_STMT_SEND_LONG_DATA` 无响应，接收错误暂存并在对应 execute 响应中报告。单对象上限通过 `[innodb] content_max_object_bytes` 配置。引擎崩溃恢复后会清除未发布的 `.staging-*` 写入目录；现已接入启动期已发布对象回收原型：在成功完成崩溃与事务恢复后流式扫描已映射用户表中的 CONTENT 引用，仅回收确认无引用的对象；发现保留 XA 清单、缺少崩溃恢复能力或无法确认 CONTENT 表映射完整时会跳过回收。该路径刚完成接线并通过服务根包构建，尚未经过事务/协议/SQL/故障注入验收，也没有纳入备份与快照保留策略，不能视为 U09 完成或通用有界 IO 已验收。大于 8 KiB 的 SQL CONTENT 值会在聚簇行编码前写入分段存储，行内保存版本化引用；切片、文本及全文函数能按引用读取相应数据。新建及更新对象引用已随 DML 变更记录传递；逻辑行回滚后清理本事务创建的对象，提交保留对象。原生 CONTENT 整列投影目前最多物化 4 MiB，超过后需显式分段读取；未实现可续传内容句柄。权限与备份恢复仍未接入，U03 尚未完成。这些源码的存在不代表事务、权限、重启或 SQL 客户端行为已全部验收；当前派生失效已有数据库目录内的进程级反向映射，以来源版本筛选候选表；首次使用从持久行重建，提交后增量更新并每 256 次相关变更写一次检查点。重启后检查点不作为权威状态加载，而从行存重建；显式共享事务回退全表扫描，候选表仍逐行检查。它尚未成为 B+Tree 管理的事务内持久索引，未经过 SQL/事务/恢复验收。向量分数也尚无 ANN 索引与优化执行器。

截至 2026-11-26，SQL 原型新增 `CONTENT_TEXT_BLOCK` 将显式文本 CONTENT 的有界字节范围包装为绑定当前行版本和原件定位的派生块；`CONTENT_TEXT_CHUNK`/`CONTENT_TEXT_CHUNK_COUNT` 提供确定性文本块访问与计数，`TABLE(CONTENT_TEXT_CHUNKS(...)) AS chunks` 表值函数可通过逗号或 `CROSS JOIN` 对前置关系行展开来源绑定块，输出块文本、typed CONTENT 块及原件字节范围。为避免扩大普通函数语法的解析冲突，表值函数采用显式 `TABLE(...)` 包装；重新生成后解析器冲突维持 46 shift/reduce、7 reduce/reduce。`RRF_SCORE` 为多个 SQL 候选名次提供确定性 RRF 分数组合。`AI_EMBED_BLOCK`、`AI_GENERATE`、`AI_GENERATE_RESULT`、`AI_SUMMARIZE` 已通过服务器注入的可替换 runtime 接入普通表、基础 JOIN 与派生投影；内容证据列身份可沿投影逐列保留，文本生成 prompt 限 1 MiB，嵌入媒体源限 16 MiB，普通 SQL 不隐式调用模型。这些是尚未行为验收的 SQL/runtime 原型，不含默认模型 provider、持久调用账本、模型目录、权限预算治理、文档导入解析、向量/全文融合执行器或 RAG 证据回答闭环。上述路径没有 SQL 行为或 MySQL 兼容性回归验收；文本分块表值函数仅处理显式文本 MIME，不提供 PDF/OCR/Office 解析。

随后新增 `AI_DESCRIBE_BLOCK(block, source_content, model_alias)` 与 JSON 结果函数。文本/表格/结构块把数据库生成的文本交给生成 runtime；图像区域、音频片段和视频帧传入来源 CONTENT 实际字节、MIME、块 ID 及原件定位，当前限制 16 MiB。函数先核验 READY 块与当前行来源版本匹配；JSON 结果额外返回来源主键/修订/摘要、块 ID、模态、MIME、页/区域/时间定位和模型版本。此项补上“模型看见实际内容且输出可追溯”的原型接口，只有服务代码构建证据，尚未 SQL、权限、调用账本及真实模型验收。见数据契约 C100。

截至 2026-11-26，`ChunkTextFromStore`、`TextChunkAtFromStore` 与 `TextChunkCountFromStore` 对外置文本 CONTENT 改为按有界范围扫描，不再限制原件必须小于 4 MiB；新增 `VisitTextChunksFromStore` 允许维护调用方逐块消费，块定位仍使用原件字节偏移并在 UTF-8 边界上切分。`CONTENT_TEXT_CHUNKS` 表值函数路径改为逐块回调生成，避免每行先收集完整 `[]Block` 后再复制成派生行，并传递查询 context 以便取消长扫描。无过滤、无排序/去重/聚合且 `LIMIT` 为非负字面量的查询现在可按偏移跳过、按数量停止生成，避免为该受限形状物化超出结果上限的块；执行器以局部状态记下已消费的 LIMIT，不改写原 SQL AST。其他查询仍物化派生行。`go build -mod=readonly ./server/...` 与 `go vet -mod=readonly ./server/innodb/content ./server/innodb/engine` 通过，尚未进行与旧分块器的差分、SQL 行为、损坏对象及取消路径验收，不能据此宣称 SQL 查询端到端流式或已具备大规模资源治理。

多模态路由随后增加严格的块种类与原件 MIME 家族校验：图像区域必须绑定 image CONTENT，音频片段必须绑定 audio CONTENT，视频帧必须绑定 video CONTENT，避免因块标签错误而把一种媒体交给不匹配的模型输入路径。`CONTENT_BLOCK_CONTEXT` 现允许通过显式 `ALLOW_DECLARED_DERIVATION` 返回与视频原件版本匹配且带起止时间定位的帧证据，并标记需要实际源模态输入；帧元数据不被当成视频像素或已验证的画面解读。该收口只有服务代码构建证据，视频抽帧处理器、定位遵循和 SQL 行为仍未实现或验收，见 C100/C101。

为让模型理解数据库数据的业务含义，内容上下文现可携带当前源 CONTENT 列与源表中经校验且状态为 `CONFIRMED` 的语义定义；关系定义还须逐条已确认，且当前 SQL 会话对关系两端全部关联列均有 SELECT 或列级 SELECT 权限。`AI_DESCRIBE_BLOCK_RESULT` 与 runtime 请求都接收这些语义。系统不会把 `SUGGESTED`/`DRAFT` 模型猜测提升为可信事实。其他列的语义、多行关联记录的上下文聚合仍待实现；这项只有构建证据，见 C102。

引擎级物理备份入口现要求引擎未启动或已成功关闭，并与 Start/Close 生命周期串行；运行中的引擎不会产生可能混合写入时点的文件快照。调用方仍须在关闭引擎前停止 SQL 监听器，底层文件快照包也仍要求完整数据目录处于停写状态。CONTENT 与派生内容的备份/恢复尚未端到端验收。

本版以通用的表、行、列、大对象、内容块、派生视图和索引组织设计。多模态是核心能力，向量检索是其中一种访问路径。Agent 使用相同的 SQL 与数据契约，受控多步执行属于后续扩展。原始、规范内容、检索和上下文的四层表示，以及完整性、新鲜度、一致性、类型保真要求，延续并收敛自前版。配套材料见[数据访问与一致性契约](2026-11-25-xmysql-data-access-contract.md)。

用户提出的“超越 pgvector”在本计划中定义为可验收的产品目标：覆盖原始多模态内容、结构化内容提取、片段定位、跨模态检索、数据库维护派生数据，以及 SQL 模型上下文和计算。向量性能须在相同条件下单独比较；本计划不声称当前 XMySQL 已具备这些能力或已优于 PostgreSQL 生态。

本文其余 SQL、类型和接口为目标设计，当前实现范围以“实施状态”及源码为准。开发基线为本分支从 `origin/dev` 的 `ba418c4` 开始；MySQL 查询兼容性阶段的范围内回归记录见[兼容验收记录](../compatibility/2026-11-25-query-compatibility-acceptance.md)。本轮 CONTENT 长参数、流式扫描和启动期孤儿回收改动用 WSL Go 1.26 对服务根包及 `./server/...` 执行 `go build -mod=readonly` 并通过；没有运行测试，因此不能据此推断 SQL 行为、事务、权限、恢复或多模态闭环通过。兼容性记录早于后续 AI 改动，仍需在最终源码上复核。工期和阈值仍须校准。

本版落实外部评审的存储契约、派生状态机、发布代际、分段索引、安全隔离和交付门槛意见。重点深化 CONTENT、派生维护和混合优化，不扩张顶层产品概念；保留通用数据库定位。原 20 到 32 周仅为未验证估计，本版撤回其作为全路线交付依据的用法，改为基线后滚动估算。各项变化与验收对应关系见第十六章。

本版进一步纳入用户要求的 MySQL AI 核心功能追平目标，固定 MySQL AI 26.10 文档能力基线，见[追平矩阵与执行入口](2026-11-25-xmysql-mysql-ai-parity-matrix.md)。矩阵区分已有基础、待实现与运行证据，不将官方功能核对或可成功构建称为已经追平。只读自然语言 SQL、多轮问答及通用文档格式纳入核心范围，通用多步 Agent 仍为后续能力。

## 一 产品目标与验收边界

### 1 统一数据库的含义

表和列是用户组织数据的入口，事务是数据发布边界，视图表达内容转换，索引提供不同检索路径，SQL 组合读取和计算。一份内容从导入到检索只有数据库维护的版本与依赖；应用无需把正文、向量和媒体引用分别写入多套数据库，再自行协调更新和删除。

一套存储指统一的事实来源、目录、权限、版本、日志与生命周期。关系页、大对象分段和索引页可以有不同物理布局；后续也可提供数据库托管的对象后端。物理分层仍由数据库管理，不能把多套独立数据库拼接后称为统一内核。

一套 SQL 指普通客户端可以表达主要操作，并遵守相同的事务、类型和错误语义。大对象通过数据库定义的流或句柄按需读取，无须把整个音视频文件展开在普通结果集中。首期关键路径不依赖专用 HTTP 业务 API、专属 Agent SDK 或外部检索服务。

### 2 超越 pgvector 的目标

pgvector 已提供精确与近似向量检索、多种向量表示及距离，并能与 PostgreSQL 的关系查询、事务和全文检索组合。PostgreSQL 本身也具有大对象能力。评估不能把这些既有能力当作对方缺失。[R14](https://github.com/pgvector/pgvector) [R15](https://www.postgresql.org/docs/current/largeobjects.html) [R16](https://www.postgresql.org/docs/current/textsearch.html)

| 维度 | XMySQL 目标能力 | 证明方式 |
| --- | --- | --- |
| 多模态内容 | 表列直接承载文档、图像、音频、视频的内容值和不可变版本 | 同一 SQL 客户端导入、读取与更新四类内容 |
| 内容结构 | 段落、表格、图片区域和时间片段形成类型化派生关系 | 通过 SELECT 回查原页、区域和时段 |
| 内容到索引 | 解析、分块、全文和嵌入随数据库依赖自动维护 | DML 后不要求应用双写或协调索引 |
| 跨模态查询 | 文字找图片、文字找音视频片段、图片找图片及关系过滤 | 模型空间兼容和来源定位专项测试 |
| 模型输入 | SQL 返回带字段解释、实际内容引用和遗漏说明的上下文 | Java Python 结果一致，模型输入可核验 |
| 内容计算 | 显式 SQL 函数执行抽取、判断与重排 | 类型、版本、预算、失败行为可观察 |
| 使用复杂度 | 导入、更新、检索、上下文在同一数据库语义内完成 | 对照记录应用同步逻辑和独立运维组件 |

产品范围更完整不等于每项检索性能领先。性能、相关性、故障恢复和运维成本分别比较，并记录组成基线所使用的插件、解析器、模型与配置。

### 3 版本交付

第一开发预览覆盖图片、PDF 和工作簿导入，以及精确检索和内容读取。多模态候选版必须覆盖音频和视频的实际内容、时间片段与查询；只有图片文档加向量时，不宣称已完成全部多模态目标。Agent 和学习型优化可以在该数据库基础上独立增加。

### 4 MySQL AI 核心追平门槛

对标 MySQL AI 26.10 的文档导入、扫描 PDF OCR、解析和分块、单条与批量嵌入、精确检索、RAG 引用、SQL 模型调用、摘要、批量结构抽取、只读自然语言 SQL 和多轮问答。文档格式要覆盖官方列出的 PDF、PPTX、PPT、TXT、HTML、DOCX、DOC；实现可以分批，但不能删减未完成格式后声称全功能追平。工作簿及原生图像、音视频属于本项目已有多模态目标，继续保留。

ANN 继续按第八章实施，HeatWave 的自动 HNSW 为独立参考基线；不能把其行为直接归到 MySQL AI 26.10。完整 AutoML、解释、漂移检测及 HeatWave 分布式加速和性能单列后续范围。功能等价是首轮目标，不承诺所有官方例程名、参数、商业部署或二进制完全兼容。

首轮验收分开报告功能、内容质量、性能和可靠性。双方同一文件、问题、模型及可比条件下运行；无法获得对照运行环境时明确“对照未运行”。OCR、RAG 和 SQL 入口是对方既有能力，差异化依赖原生内容版本、派生维护、关系与多模态组合的具体证据。

### 5 开发分支的兼容性与增量扩展约束

本分支在现有 XMySQL 上增加多模态、RAG 和 AI，尽可能保持当前 MySQL 能力及使用方式。既有 SQL、协议、事务、权限、存储、恢复、复制和运维路径都属于回归范围；不能通过裁掉旧功能、建立简化 SQL 子集或改成专用 AI 服务来完成新增目标。当前读取来源为 dev 工作区，开发起点及用户已有修改须在隔离实现分支中固定和保留。

“当前能力”以可复现的实现和行为证据为准，不等于上游 MySQL 的全部功能，也不能从现有兼容文档推定全部通过。P0 对每项分别记录已验证、已实现待验证、已有失败、未支持和未覆盖，附命令、版本及结果。已有失败单列原因，不删除测试、不把失败改成正常空结果；安全、事务和数据可靠性的阻塞问题先解决。必要的缺陷修复可改变错误行为，但须明确修复目标、兼容影响及回归证据，不能把保留能力解释为冻结已知缺陷。

| 保留范围 | 新功能接入约束 | 主要证据 |
| --- | --- | --- |

新能力默认关闭或显式启用。没有调用内容或 AI 扩展的普通 SQL 不触发解析、模型请求、外发或收费；模型不可用不得阻止基础服务启动及旧表查询。已有数据库、表和系统元数据不强制迁入另一套格式，原有对象含义与结果列保持兼容；新增目录采用可识别版本及明确迁移。新增函数不得覆盖同名已有对象，新关键字不得随意把原可用标识符变成语法错误。

兼容性检查以[现有 MySQL 8.4 矩阵](../compatibility/mysql84_compatibility_matrix.md)、相关协议和引擎测试为入口，扩展到实际支持范围。每个阶段同时运行旧功能集和新功能集，并比较同一版本在新能力关闭、开启及混合负载下的普通 SQL 行为。向上游 MySQL 的差分验证另列版本和已知偏差；旧 XMySQL 回归通过不能直接宣称上游全兼容。

同一固定用例集上，原通过能力出现新的结果、类型、错误、事务或权限回归时阻止对应阶段发布，不允许通过跳过旧测试降低门槛。资源与延迟按固定基线报告，普通 SQL P95 增幅目标沿用第十五章，阈值与负载在验收前冻结。测试准备和回归分别落入 U01 与 U20，不另建替代执行引擎。

关闭 AI 功能不等于旧二进制可直接读取新目录或 CONTENT 数据；降级与回退必须按第十五章验证格式、读者兼容和备份恢复。普通 MySQL 工具对新增类型的支持单独验证，不能因旧表导出成功就宣称 CONTENT 也可自动恢复。

## 三 用户数据模型与 SQL 使用方式

### 1 对外概念收敛

| 数据库概念 | 增加的能力 | 用户无需管理的内容 |
| --- | --- | --- |

| 大对象值 | 类型、版本、摘要和流式读取 | 外部路径与数据库引用的双写 |

模型和解析器属于可版本化的数据库执行依赖，管理员配置后由 SQL 引用。普通应用不必为每份文档创建一套模型、流水线、资源实例和任务接口。

### 2 导入和直接读取

以下 SQL 为拟议语法，用于固定产品表达方式，并非当前可执行脚本。CONTENT、表值函数、派生物化视图和新索引语法都需要解析、绑定和执行器建设。

```sql
CREATE TABLE documents (
  id BIGINT PRIMARY KEY,
  category VARCHAR(100),
  body CONTENT
);

INSERT INTO documents(id, category, body)
VALUES (?, ?, CONTENT_FROM_BYTES(?, 'application/pdf'));

SELECT id, CONTENT_METADATA(body), CONTENT_TEXT(body)
FROM documents
WHERE id = ?;
```

示例将 MIME 类型作为固定字面量，原始字节使用一个绑定参数。当前协议流式接线只识别这种固定 MIME 的 `CONTENT_FROM_BYTES(?, '<literal MIME>')` 预处理参数；动态 MIME 参数仍可能走内存缓冲路径，不能把它描述成流式支持。Java 使用标准 PreparedStatement；可用时通过 setBinaryStream 发送长参数，Python 使用经过验证的 MySQL 驱动发送有界参数。对于超过驱动单次承载能力的内容，提供同一连接上的 SQL 大对象写入与读取句柄。驱动可能缓存数据，必须测量客户端与服务端内存，不能因 API 名含 Stream 就宣称端到端流式。

单对象上限由 `[innodb] content_max_object_bytes` 配置，默认 1 TiB；服务端每次分段写入都会累计校验，不超过数据库设定上限。它限制单个原件，并不替代按用户的并发上传配额、总容量治理、断点续传或 GC。

内容写入完成后随 INSERT 或 UPDATE 提交；查询原件无需等待 OCR 或嵌入完成。调用 CONTENT_TEXT 等派生读取函数时，是否等待处理就绪由查询策略决定。处理失败返回数据库可识别错误，不伪装成空正文。

### 3 内容关系与检索

```sql
CREATE MATERIALIZED VIEW document_blocks AS
SELECT d.id AS document_id, d.category,
       b.block_id, b.text, b.source
FROM documents AS d
CROSS JOIN LATERAL CONTENT_BLOCKS(d.body) AS b;

CREATE INDEX blocks_vector ON document_blocks
  (AI_EMBED('encoder_v1', text)) USING HNSW;

SELECT document_id, block_id, text, source
FROM document_blocks
WHERE category = ?
ORDER BY VECTOR_DISTANCE(
  AI_EMBED('encoder_v1', text),
  AI_EMBED('encoder_v1', ?))
LIMIT 10;
```

派生视图是数据库声明式维护对象，其源表、内容版本和解析配置进入现有目录依赖体系。默认严格读取需要指定来源范围全部达到所需能力，未满足时等待或返回未就绪；允许部分读取须显式选择并披露覆盖。默认使用精确语义，只有查询显式允许近似时才能选 HNSW；表达式索引必须匹配固定模型版本及编码参数。

索引表达式中的源嵌入先成为数据库维护的持久派生值，绑定来源内容、模型与编码配置版本；精确扫描和 ANN 索引读取同一个值，不能因为选择不同计划就重新推理源向量。上例的表达式索引是该内部派生值与索引的语法简写。查询参数的向量每条语句只计算一次并固定，重建或重新嵌入须产生新的派生版本和明确切换。固定模型名本身不能证明推理结果完全确定。

表格精确统计读取类型化表格关系，不对检索 Top K 或重叠分块求和。短文档、编号过滤和按页读取均可直接走关系路径，不要求先向量化。

### 4 获取模型上下文和显式计算

CONTEXT_AGG 聚合选定结果，返回字段说明、实际文本、受控内容句柄、来源与遗漏信息。上下文是 SQL 查询结果的一种类型化表示；可以交给外部模型，也可以由显式 AI_EXTRACT、AI_MATCH 或 AI_GENERATE 函数消费。普通 SELECT 不自动调用收费模型。

上下文中的媒体句柄供适配器读取原图、原页或音视频片段。只有地址或向量而无实际内容的输入，不算完成多模态输入适配。模型原生支持的视频或音频可直接输入；降为关键帧、转写或描述时说明观察范围和信息损失。

### 5 多模态 SQL 示例

下面的拟议查询直接对内容列和片段视图计算。图像与文字使用注册为同一兼容空间的 multimodal_v1；模型不支持该模态或空间不兼容时应报错。

```sql
SELECT id, CONTENT_METADATA(body)
FROM documents
WHERE category = 'image'
ORDER BY VECTOR_DISTANCE(
  AI_EMBED('multimodal_v1', body),
  AI_EMBED('multimodal_v1', ?))
LIMIT 10;

SELECT a.id
FROM documents AS a
JOIN documents AS q ON q.id = ?
WHERE a.category = 'image'
ORDER BY VECTOR_DISTANCE(
  AI_EMBED('multimodal_v1', a.body),
  AI_EMBED('multimodal_v1', q.body))
LIMIT 10;

SELECT s.start_ms, s.end_ms, s.source
FROM documents AS d
CROSS JOIN LATERAL CONTENT_SEGMENTS(d.body) AS s
WHERE d.id = ?
  AND AI_MATCH('review_v1', s.content, ?);
```

第一个查询以文字检索图片，第二个以已有图片查相似图片，第三个对固定内容的音视频片段执行显式语义判断并返回原时间位置。全文、转写和向量是可选访问路径，实际判断需要读取所声明的片段内容。相关索引可以加速前两个查询，不能未经授权把精确模式自动改成近似。

## 四 统一内核架构与复用边界

### 1 请求路径

```text
Java Python 与其他 MySQL 兼容客户端
                 │
          SQL 解析 类型与语义绑定
                 │
         关系 内容与语义查询优化器
                 │
    扫描 关联 聚合 内容读取 全文 向量 模型算子
                 │
      同一事务存储 元数据目录与依赖管理
          │                  │
      关系页与索引页      托管大对象分段
                 │
       数据库维护作业与可替换执行部件
        解析 OCR 编码 解码与模型推理
```

Agent 位于客户端或受控 SQL 执行层，不形成另一套事实存储、权限体系和查询入口。后台解析和模型计算可以独立进程部署以隔离故障，但输入输出必须回到数据库目录和事务发布协议。用户无需同步另一套检索数据库。

### 2 现有机制优先复用

表列目录管理内容 Schema，视图目录记录转换表达式，索引目录管理构建水位与切换，事务日志记录发布，现有权限检查覆盖源列和派生读取。扩展后台调度的持久化与租约能力，用同一个维护作业框架处理解析、视图刷新和索引重建。

需要新增的是内容值编码、大对象后端、规范内容结构、派生依赖维护及相关计划节点。新增逻辑包服务这些职责，暂不建立独立 Agent 平台、知识库系统或通用工作流产品。现有机制不能满足原子性或隔离要求时，明确补齐内核能力后复用。

### 3 参考资料的用途

Lance Blob 的延迟与局部读取可供物理布局参考；MariaDB 内部表表达向量图可供事务索引参考；LOTUS 说明语义算子可以纳入查询优化。这些资料不意味着直接更换 XMySQL 存储格式或引入外部向量数据库。[R1](https://lance.org/guide/blob/) [R5](https://mariadb.org/mariadb-vector-how-it-works/) [R4](https://www.vldb.org/pvldb/vol18/p4171-patel.pdf)

MinerU 到 Markdown、Embedding 再到 Milvus 的常见链路，仅用于分析提取、表示、分块和候选检索的职责。XMySQL 将这些职责表达为内容视图和数据库索引；解析器是内部可替换部件。MinerU 官方输出中阅读格式和结构化中间结果承担不同职责，具体版本需要单独适配。[R13](https://opendatalab.github.io/MinerU/reference/output_files/)

## 五 四层表示与规范内容关系

### 1 一份来源的不同表示

| 层次 | 数据库表达 | 权威范围与维护 |
| --- | --- | --- |
| 原始表示 | 普通行版本及 CONTENT 大对象值 | 原始字节与类型化值，提交后不可变来源身份 |
| 规范内容 | 派生视图中的块、单元格、区域、片段 | 解析版本、结构、顺序、位置与质量 |
| 检索表示 | 全文与向量等索引及其内部候选记录 | 来源与分块版本、模型空间和覆盖水位 |
| 上下文表示 | 查询结果、CONTEXT_AGG 及可选物化结果 | 本次选中内容、解释、预算、来源与缺口 |

这些是逻辑表示，可共同存于数据库页、大对象分段与索引，不各自建立独立数据库和对外服务。原始数据是事实源，派生表示按依赖可重建；索引只承担定位能力，不能替代原文和媒体内容。

### 2 规范内容结构

规范内容由有序 ContentBlock 及关系构成。块类型覆盖标题、段落、表格、单元格、图像区域、音频片段和视频片段。基础字段为 source_ref、content_revision、block_id、kind、parent_id、order_key、typed_value、locator、extraction_method、quality_state。

source_ref 绑定源表、列、主键和行版本，以及不可变内容 ID 与版本。结构块按单个 content_revision 定义身份，不能假定解析器升级后块编号仍有同一含义。表格保存列类型、行列、合并关系及原始单元格映射，数值进入精确计算时保留 DECIMAL 或整数等本机逻辑类型。

PDF 页码从 1 开始，图片区域采用归一化坐标并记录尺寸和变换。音视频使用原件时间轴的毫秒半开区间，保留实际采样帧时间、音轨和时钟偏移。字节范围不等同于时间范围。内容间关系使用源行外键、内容父子关系或声明式连接规则，不预设行业实体。

### 3 视图与分块

Markdown、HTML、类型化 JSON 和模型消息均从同一规范内容版本形成视图。Markdown 适合阅读，复杂表格、精确数值、坐标和公式状态应读取结构化关系。无法表达的原件特性通过转换诊断及原始内容引用保留，不宣称完全无损。

检索 chunk 作为索引内部结构或可查询派生视图，记录内容块范围、chunk_profile、tokenizer、重复上下文和来源。按章节、表格和时间区间分块；拆分时保留连续与父子关系。重复表头和窗口重叠标记 context_only，精确聚合按原始行或单元格身份去重。

解析器、分块器或编码输入变更时形成新派生版本，依赖维护器重建相应视图与索引。提示词升级只影响真实依赖它的计算，不无条件重建所有索引。

## 六 大对象与事务一致性

### 1 内容值与物理布局

CONTENT 是不可变原件的逻辑值，行记录保存有版本的描述符。SQL 更新内容列时建立新的内容修订或引用另一个已存在值，不原地覆盖旧字节；同一修订的 MIME、长度和摘要不可修改。VECTOR 是具有维度和编码空间的数值类型，不能代替内容值。

| 描述符字段组 | 规范性含义 | 存储约束 |
| --- | --- | --- |
| format_version、flags | 描述符编码及特性版本 | 固定端序与长度前缀，未知必需特性拒绝读取 |
| content_id、revision | 数据库分配的内容身份及不可变修订 | 唯一键；不是裸文件路径，也不是访问凭据 |
| mime_type、size_bytes | 经格式校验的类型及字节长度 | MIME 为有版本目录编码；长度做溢出与上限检查 |
| content_sha256 | 原件完整字节摘要 | 上传完成时验证；分段另有校验，不把后端 ETag 当摘要 |
| storage_kind、manifest_id | INLINE 或 MANAGED_SEGMENTS 及清单定位 | INLINE 直接带字节；分段清单固定序号、长度、摘要和内部对象键 |
| ownership_ref | 所属数据库及授权域内的目录引用 | 权限由来源表列和当前身份判定，描述符不能自授权限 |

此表是逻辑字段契约，不将 Go struct 的内存布局直接写盘。P0 确定编码头、整型宽度、最大长度、校验范围、可选字段跳过规则与迁移测试；P1 前冻结 v1 编码。内容修订、清单和段均不可变，引用计数或引用表、GC 标记及发布状态保存于事务目录中，不混入不可变内容的摘要。

P1 先实现数据库托管文件分段这一条大对象路径，描述符预留 INLINE；是否启用小值内联、阈值和段大小由基线测量确定，不同时开发四种存储后端。普通投影不加载未请求内容列，范围读取只读所需段。行、目录、LOB 缓存分别核算，句柄不得暴露物理路径。后续托管对象存储复用同一目录和清单；纯外部引用另行声明更弱的保留与恢复保证。

首期经兼容二进制或文本编码跨 MySQL 协议传输，显式 SQL 转换保留类型说明。普通客户端不必识别未知线协议类型；导入采用二进制参数，读取采用元数据和受控句柄，不把描述符文本误认为原件字节。

### 2 提交与增量维护

长参数或大对象写入先完成持久化与摘要校验，再在同一事务内提交源行、内容引用和派生维护意图。回滚不发布引用和维护意图。上传完成而未提交的孤儿对象可以回收；已提交内容不能指向未完成对象。

维护意图包含源表列、主键和版本、目标视图或索引 ID、定义版本。后台作业消费已提交意图，在事务外解析或推理，短事务校验租约并写派生结果。针对当前视图的目录指针采用版本比较后切换；合法历史来源的结果可按版本保存，不覆盖新来源的当前指针。

该机制同时服务 OCR、视图刷新、嵌入和索引维护。内部可以使用事务 outbox 形态实现，但无需用户部署消息队列、同步连接器或额外任务数据库。调度启停可复用已有后台生命周期，持久领取、重试和 fencing 需要新增并验证。

### 3 回收 备份与恢复

逻辑删除解除当前行引用，物理回收等待活跃 MVCC 读者、结果句柄、维护作业及备份不再需要该内容。对象目录使用 READY、DELETING、DELETED 和删除代次；绑定与 GC 锁定同一目录记录，避免检查无引用后又被绑定的竞争。

缺少可靠读者水位时禁用在线物理回收，采用停写清理。备份固定关系与目录恢复点并列出不可变对象、视图和索引版本。首期允许短时停写建立一致清单；在线备份必须单独验证。索引可重建，原始内容和目录清单必须可恢复。

## 七 声明式派生与多模态处理

### 1 派生视图维护规则

内容解析是确定版本处理器定义的派生计算，注册为内容视图依赖。用户声明所需视图或索引，数据库决定执行时机、进度、重试和失效。处理状态与定义进入系统目录，通过 SQL 查看；不要求应用编排每次解析、编码和写索引。

默认异步维护原件的计算结果。读取原件保持独立；读取必须就绪的派生列时遵循严格等待和覆盖要求。同步计算仅用于明确的小规模、可预算操作，不能在持有存储闩锁时等待远程模型。模型或解析失败不回滚已经成功提交的原始内容，而是在派生能力状态中可见。

### 2 派生身份与状态转换

派生身份 D 由来源表列与主键、源行版本、content_id/revision、派生定义版本、处理器与配置版本、规范模型与分块版本，以及实际用到的模型空间和语义版本组成。无关依赖填不适用，不把每个模型变化都传播到所有视图。重试共享 D，但有独立 attempt_id、单调递增 fencing_token 和租约；发布代际是独立字段，不用一次运行编号替代依赖版本。

| 原状态 | 条件与动作 | 目标状态及约束 |
| --- | --- | --- |
| 无记录 | 已提交维护意图创建 D | PENDING；未提交源行不能被 Worker 发现 |
| PENDING | 原子领取并分配租约和 fencing_token | RUNNING；同一时刻只有当前令牌可发布 |
| RUNNING | 结果持久化，依赖、质量及令牌通过校验 | READY；结果与状态同一短事务提交 |
| RUNNING | 内容有效但质量须复核 | REVIEW_REQUIRED；不冒充质量达标 |
| RUNNING | 可识别失败或不可恢复输入 | FAILED；记录原因、重试资格及影响单位 |
| RUNNING | 租约超时且接管者提高令牌 | PENDING；旧 Worker 即使返回也不能发布 |
| FAILED | 显式重试或有界自动重试 | PENDING；新 attempt，次数及退避有上限 |
| REVIEW_REQUIRED | 人工纠正或改变处理定义 | 新 D 的 PENDING；不覆盖旧证据 |
| 任一状态 | 不再属于当前定义或来源 | OBSOLETE；失去当前资格，合法历史结果仍可保留 |

READY 是该 D 的运行就绪状态，不等于某个视图代际已对外发布。历史结果不因当前指针变化而失去其来源身份；OBSOLETE 也不要求马上删除历史字节。故障恢复重领作业前先核对已提交结果及令牌，禁止因回应丢失重复发布或覆盖当前结果。

### 3 完整代际与原子发布

物化视图可以把固定来源清单、定义集合和必要能力组织为发布代际 G。内部代际状态采用 BUILDING、SERVING、RETIRED；这些是现有派生视图目录的状态，不新增用户必须操作的资源。BUILDING 可持续接收结果，显式已发布代际入口只指向已验证的 SERVING 代际；普通视图名不因此默认切到旧来源。

发布清单保存 generation_id、source_manifest_id、source_snapshot_id、定义及能力集合、预期单位与结果摘要、无洞覆盖前沿和 previous_generation_id。只有约定范围内全部必要项 READY 且质量合格，才允许在同一目录事务内通过 CAS 更新服务指针。失败、待复核、取消或预算耗尽阻止该完整代际发布，原服务代际仍可读；调用方可重试、修复或显式建立不同范围，不能悄悄丢弃坏页后声称全量完成。

增量代际通过清单复用未变化的不可变产物，仅处理变化依赖；仍逐项验证新范围的完整覆盖。发布只核验目录与摘要，不在该事务内读取全部媒体或执行模型。构建完成前崩溃只留下不可见产物；指针提交后崩溃通过目录恢复同一 G。旧代际由 MVCC、句柄及备份保留，不能切指针后立即回收。

P2 代际粒度固定为“物化视图、定义版本、授权分区”的定义范围，不为每条临时 SQL 全库重建。跨分区读取需验证共同来源切点；无法证明一致时返回 CONSISTENCY_UNAVAILABLE。代际可服务其授权子范围，但不能宣称覆盖范围外来源。同一视图、定义及分区的服务前沿只能前进，CAS 同时检查前驱、覆盖前沿和定义版本。较旧构建 CAS 失败后不能重读指针再覆盖较新代际，只可保留为历史产物或废弃；新定义另建发布序列，经显式兼容性检查才切换逻辑定义绑定。

P2 首期选择持久保存代际所需的关系投影：主键、源行版本、视图定义依赖的字段值、类型及内容修订引用与清单一起持久化。未变化投影可复用不可变记录；G 持有内容引用，参与 GC 和备份。读取不依赖无限延长普通事务或新增通用历史查询能力，重启和源行回收后仍可重建该代际。新查询需要未保留字段时不能向当前源行补读，应按当前来源重查或返回范围不支持。

P1 的 U08、P2 默认 CAPTURED_SOURCE 查询均可以直接读取选中来源对应的 READY 产物，只要求该查询所需单位完整就绪；范围外坏文件不阻塞。LATEST_PUBLISHED 才选择完整 G，不能读取 BUILDING 的已完成子集冒充发布成功。固定查询中有缺失项则返回 NOT_READY 或处理失败；全视图的完整发布门槛与逐查询严格覆盖是两个不同边界。

### 4 文档与工作簿

PDF 逐页枚举，区分数字文本、扫描图像、混合页和旧 OCR 层。数字文本直接提取，扫描页渲染后进行版面与 OCR，混合页按区域合并去重。每页有独立状态，空白分类、提取失败、待复核和未处理不能合并为空字符串。

工作簿先保留原件，再依导入视图映射为类型化表。保留 Sheet、单元格、表头、合并关系及排除范围。公式文本、缓存值和重新计算结果分开，外链不可用、缓存未验证和计算错误有显式状态。编号前导零、DECIMAL、币种与无时区时间不无声转换。

### 5 图像 音频与视频

图像保留原图、旋转与区域变换，可产生 OCR、视觉向量和结构化抽取结果。音频保留原始音轨及时间片段，转写和声学向量分别有能力状态。视频维护关键帧、片段和音轨的时间映射，查询可回读实际片段或声明的观察表示。

不同模态不强制压成一段描述文本，也不强制用同一个向量概括整份原件。索引可以并存全文、视觉、语音和视频片段向量。直接跨模态距离仅允许在注册为兼容的空间内进行；不兼容模型通过候选融合与核验组合，分别披露召回和观察范围。

### 6 处理资源与范围

首批格式白名单为 JPEG、PNG、未加密 PDF 和 XLSX；核心追平阶段增加 TXT、HTML、DOCX、PPTX 及受限转换的 DOC、PPT，按 U30 逐格式验收；音视频阶段固定选定编码与容器并单独验收。图像、页数、像素、持续时长和解码内存均有限额。解析与解码使用独立 Worker 隔离，配置及实际资源开销由数据库管理。

## 八 索引与混合查询优化

### 1 索引语义与分段路线

全文、向量和时间索引属于同一索引目录。精确和 ANN 均读取已持久化的同一源嵌入；源向量版本与模型空间固定，查询向量每条语句计算一次。近似搜索仍须核验源行可见性、删除及权限，返回索引代际、覆盖和近似标志；全库 Top K 后过滤不能冒充条件集合的精确 Top K。

| 步骤 | 实现边界 | 退出条件 |
| --- | --- | --- |
| A 精确基准 P2 | 持久向量列、关系过滤、精确距离与 Top K | 独立真值、类型与来源一致 |
| B 不可变 ANN 段 P3 | 固定向量清单离线构图，段文件持久化，再原子切换目录 | 构建崩溃不可见；重启和旧读者正确 |
| C 基段加持久增量 P3 | 同一事务目录下的 delta 与删除记录；后台合并段 | 并发更新、删除、切换和恢复不漏不重 |
| D 可变事务图 远期可选 | 仅在分段方案实测不足时研究在线改边与日志 | 独立设计与收益证据，不是候选版前置条件 |

增量是数据库持久记录，不是仅在内存中的缓冲。已完成嵌入的变化与其 delta 发布原子关联；源提交而嵌入尚未完成时仍为 NOT_READY 或显式旧代际读取，不能宣称新来源已索引。每次查询固定段清单、来源清单、delta 读取快照和覆盖前沿；扫描基段与当前快照的 delta，经修订键和删除记录裁定可见版本、去重再排序。delta 初期精确扫描，其增长会增加尾延迟，触发有界合并和背压，不静默跳过。

合并在固定截止点 C 构建新段，C 后变化继续进入持久 delta。新清单提交时将产物清单、已吸收的 delta 范围、删除覆盖和前沿一起 CAS 发布；读取固定新旧清单之一，不能混用段和截止点。C 之前记录仅在旧读者与备份退出后回收。重启丢弃内存缓存，依据日志和清单重建，不依赖图缓存恢复事实。

MVCC 过滤掉新版、删除或无权候选后须继续探索或按已声明策略回退扫描，不能只过滤首批 K 条；耗尽预算仍可少于 K，但披露原因、实际候选数和近似性，不声称全量。ANN 基段加精确 delta 的融合依旧是近似结果，增量扫描完整不证明语义召回完整。Lance 的版本化索引及未索引数据扫描、Qdrant 的不可变结构提供参考；本项目的发布与事务语义仍需自行验证。[R18](https://lance.org/guide/indexing/) [R19](https://qdrant.tech/articles/immutable-data-structures/)

### 2 计划选择

优化器在关系过滤、内容投影、全文候选、精确向量、ANN 和重排之间选择执行路径。高选择性条件可先取源行 ID，再读向量；语义与全文融合初期采用明确的排名融合规则，不直接相加不同量纲分数。多模态候选按内容身份和片段版本去重。

物理计划扩展 ContentScan、ContentBlockScan、VectorExactScan、VectorIndexScan、SemanticFilter、ContextAggregate 及后述融合、重排和证据节点。支持延迟读取原件、批量推理、取消和背压。EXPLAIN 输出真实执行计划；ANALYZE 记录实际行数、候选数、字节、解码、推理和缓存，不用文本推断代替权威计划。

### 3 混合优化的首期决策规则

首期采用可解释规则加成本估算，不等待学习型优化。先下推授权与可精确计算的关系条件，再按过滤后基数、索引覆盖、delta 大小和内容字节选择路径。小候选集优先精确距离；大集合且允许近似时考虑 ANN；全文与向量按明确规则融合，只有显式语义操作才调用模型。

例：同一查询把过滤后范围从十万行缩到几十行时，可以由 ANN 改为关系索引加精确向量扫描；阈值由固定硬件测量，不在语法中硬编码。更换路径不能改变源嵌入、来源版本或精确性要求。先做距离和全文召回，再按预算读实际页面或片段并重排，避免对所有大对象逐行解码。

统计量至少包括过滤基数及误差、每模态平均与分位内容大小、向量维度和分布、索引覆盖、delta 字节及数量、解码和模型批次耗时。EXPLAIN 展示选择原因、拒绝候选路径和估算单位；ANALYZE 对照实际开销，形成后续校准样本。计划失误可回退已验证路径，但不得放宽 SQL 指定的精确性、新鲜度或预算。

### 4 成本与预算

分别估算 IO 字节、CPU、内存、解码时长、模型请求、token 和远程延迟，在目标约束下选计划。保留单位，不将货币、毫秒和字节直接相加。并发调用先预留预算；未知是否成功的远程请求保留账目，不能通过重试绕过预算。

精确与近似语义由 SQL 查询策略决定，不因预算紧张静默更换。未来学习模型用于校准基数和候选计划，先离线与影子评估，再限定负载采用，并保留传统优化路径。[R7](https://rmarcus.info/bao_docs/)

### 5 检索质量的执行链路

RAG 检索质量包含内容表示、候选召回、排序、上下文覆盖和证据可用性。精确向量只对既定编码空间的距离负责，ANN Recall at 10 的 0.95 是相对于精确近邻的目标，不能解释为 95% 的证据相关性或回答正确率。事务、权限和版本正确可以减少错误来源，但不直接证明语义相关。

执行链路为：固定查询与授权来源 → 类型和条件绑定 → 关系、全文、文本或多模态向量召回 → 候选去重与融合 → 读取实际内容并重排 → 结构化上下文补全 → 证据检查 → 生成与引用 → 最终回答核验。复用现有目录、优化器和执行器，不增加必须由应用部署的检索中间件。

| 环节 | 内核职责 | 必须保留的证据 |
| --- | --- | --- |
| 内容表示 | 章节与段落、表格行列、单位、区域和时段形成规范内容关系 | 处理版本、质量状态、父子及连续关系 |
| 查询绑定 | 识别明确字段、编号、日期和版本条件；歧义不自行猜定 | 有类型的谓词、范围及语义定义版本 |
| 多路召回 | 在同一授权及来源范围使用关系索引、全文和兼容向量空间 | 通道、候选预算、原始排名、空间及索引版本 |
| 融合重排 | 按证据身份去重，融合排名，再联合问题和实际内容评分 | 融合配置、重排模型、入选及淘汰原因 |
| 上下文补全 | 补表头、单位、限制条件、相邻段落或必要媒体片段 | 实际读取位置、补全关系、截断与未观察范围 |
| 证据和回答核验 | 区分数据访问完整、语义证据充分和回答受支持程度 | 缺口、冲突、主张到证据映射及核验方式 |

检索策略作为 SQL 显式参数或已有视图的版本化选项，编译为内部 retrieval_profile，包含通道、各路 candidate_limit、融合规则、重排能力、上下文预算、补查上限及证据策略。用户可以直接传参数，无须新建专门资源。策略摘要参与查询复现及缓存依赖；模型、分块或策略升级不得复用不兼容的旧评分。

普通 SELECT 不隐式触发查询改写、重排或生成。ORDER BY VECTOR_DISTANCE 指定距离顺序时，必须保持其排序语义；只有显式 RAG 或语义排名操作才按声明策略融合与重排。精确统计、编号定位、版本过滤优先使用类型化关系路径，不强制进入模型。

### 6 多路召回与重排

全文通道采用可版本化分词、字段权重及 BM25 等评分，保留专有词、精确短语和编号路径；文本向量补充同义表达，多模态向量按各自兼容空间工作。中文分词、大小写及标点归一化均需在词面测试集中校准，不能通过归一化改变编号或数值身份。原始问题保留；查询扩展默认关闭，显式启用时不得改变已绑定的版本、数值、单位和权限条件。

各通道使用相同来源清单与授权边界，不先对全库取 K 再过滤作为默认路径。优化器按选择性选择先过滤后扫描、允许的 ANN 探索或精确回退；过滤、删除和版本裁定后不足候选时，有界增加探索量。预算耗尽返回实际覆盖和不足原因，不隐式放宽谓词。精确模式不能因为候选少就放入条件不符的材料。

首期融合采用 RRF：对同一证据的各通道名次 r 求加权 1/(c+r) 之和，c 和权重随策略版本固定；不直接相加全文分数、向量距离和模型评分。候选按来源修订、规范块或媒体区间身份归并，保留每个通道的贡献；相似但来自不同来源或版本的证据不能无条件合并。RRF 是融合基线，其收益仍需本项目消融验证。[R22](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)

重排读取问题与候选实际文本，或模型支持的原图、页面与片段，不仅消费向量和路径。文本可采用跨编码器或受控语义模型；不同模态须有能力匹配，降为转写或描述时披露损失，不能宣称已核验原始媒体。批次结果与候选 ID 逐项对齐，分数仅在相应模型和策略内解释，不使用跨模型通用置信阈值。二次重排已有官方实现可参考，但不代表本项目已经获得同样收益。[R23](https://learn.microsoft.com/en-us/azure/search/semantic-search-overview)

首期用若干候选预算配置在校准集比较召回、重排开销与尾延迟，不把某个 Top K 写成所有问题的固定最优值。更深召回、重排超时和能力不符按显式策略报错，或在允许时降级并标注实际执行模式；不能在要求重排的严格请求中静默返回初排。涉及模型的步骤先预留请求、token 和媒体处理预算。

### 7 上下文补全与证据检查

命中块保留 parent_id、相邻关系、表格行列及来源定位。ContextExpand 依据问题和声明规则补齐标题、表头、单位、限制条件、必要邻段和媒体前后片段；补全只能从同一固定来源及当前可授权内容取得，不能拼接当前源行或另一修订。重叠内容以规范身份去重，补充表头等标记 context_only，不能参与重复统计。

所有实际输入形成 context_manifest，记录原件、提取与转换版本、区间、裁剪、模型输入表示、质量、加入原因及未包含的依赖。预算不足时优先保持必要结构；无法保留表头或关键限制条件须记录缺口，不能无声截断后声称上下文完整。音视频扩展受时间与解码预算限制，未观察区间保留为未知。

EvidenceCheck 先做确定性检查：来源可读、版本吻合、位置有效、关键字段和单位可解释、所需计算有结果。语义充分性与冲突判断另记评估方式；模型判断只是派生推断，不是完整性证明。可进行有上限的补充召回或澄清，不允许无限 Agent 循环补查。

数据访问的 result_status 与回答的 answer_status 分开。满足固定来源处理和传输契约时，result_status 可以是 COMPLETE，同时 answer_status 为 INSUFFICIENT_EVIDENCE、CONFLICTING_EVIDENCE 或 NEEDS_CLARIFICATION，answer 为空并附允许披露的原因。UNASSESSED 表示未作语义评估，不能显示成充分。REQUIRE_ALL 约束来源处理覆盖，不强迫模型肯定回答；如果调用方另设 require_supported_answer，无法满足时返回 EVIDENCE_REQUIREMENT_UNMET。仅有近似未命中不能证明材料不存在。

### 8 执行诊断与复用

计划增加 CandidateUnion、RankFusion、Rerank、ContextExpand 和 EvidenceCheck 节点，落在现有内容计划及执行器中。EXPLAIN 展示通道、谓词、精确性、各路预算、策略与模型版本；ANALYZE 记录各路命中、过滤淘汰、融合去重、重排、补全、截断、补查次数、耗时及用量。无权调用方只能查看授权范围的诊断，不能通过候选数或淘汰原因枚举隐藏来源。

排查按内容未提取、召回未命中、融合淘汰、重排降位、补全缺失、来源失效或生成无依据逐层归因。复用缓存需匹配问题和参数、来源及语义版本、向量空间、处理与检索策略、重排和生成模型，并重新校验当前授权。保存结构化诊断引用，完整提示词和内容不直接进入普通日志。

### 9 检索质量的校准与发布

在既定独立问题集中明确至少 200 道 RAG 问题，其中至少 40 道无匹配、证据不足、冲突或歧义反例；另保留至少 100 道 SQL 问题及其中至少 20 道反例。按原件及其修订族切分校准集和验收集，防止同源内容通过不同块或版本跨集泄漏。P2、P3 按适用模态标明范围，未支持模态不计为通过。

RAG 标注同时包含相关性等级、必须证据组、每组可替代证据、位置、期望结论及允许的拒答。多跳问题需命中各必要组，不把只命中其中一个块算作证据完整。由独立参考答案与人工抽样复核质量，不能仅由生成模型自评。指标及分母见第十五章与配套契约，阈值在验收前按任务和模态冻结；没有相关性标注就不能声称检索精度已达标。

消融分别比较全文、向量、融合、重排及结构补全，在相同来源、模型、问题和资源条件下记录收益与退化。ANN 另以相同持久向量的精确扫描作真值；该实验与相关性、答案实验分别报告。策略更新先离线验收，再小范围只读发布和版本回退，不能通过删除难题、调低回答覆盖或更换验收分母制造改进。

## 九 数据解释与 SQL 模型计算

### 1 复用元数据解释数据

字段解释、单位、枚举、空值含义和连接关系扩展现有表列与视图元数据。声明的指标复用类型化表达式 AST。可从 COMMENT 和现有 Schema 导入初稿，再补充机器可读定义；AI 建议与已确认定义分开保存。没有必要先建立一套行业实体平台才能查询内容。

首个语义目录实现复用现有 MySQL `COMMENT` 持久化路径：`xmysql-semantic:v1:` 后跟 JSON，含正整数 `revision`、`status`、`source`、业务名称/解释，以及列级单位/空值含义/范围/枚举映射和可选模型建议置信度。表级定义还可列出命名关系、目标表、两侧列、基数、业务含义和独立确认状态。状态区分 `DRAFT`、`SUGGESTED`、`CONFIRMED`、`REJECTED`；模型来源不能标为 `CONFIRMED`，确认项必须声明 `confirmed_by`。普通 COMMENT 不解释为语义事实；带前缀但格式非法的定义会在 `information_schema.xmysql_column_semantics` 或 `information_schema.xmysql_table_semantics` 以 `INVALID` 和错误说明暴露，不静默丢弃。目录行遵循表及列权限，只显示当前用户可 SELECT 的列；关系目标不可见时会省略目标并标记关系已裁剪。当前定义随 COMMENT 一起持久化，但只保留当前 revision；历史版本和模型上下文消费仍待完成。

```sql
CREATE TABLE documents (
  id BIGINT PRIMARY KEY,
  title VARCHAR(200) COMMENT 'xmysql-semantic:v1:{"revision":1,"status":"CONFIRMED","source":"MANUAL","confirmed_by":"schema-owner","business_name":"Document title","description":"Human-readable title shown to users"}'
);

SELECT table_schema, table_name, column_name, status, business_name, description
FROM information_schema.xmysql_column_semantics;
```

表关系使用同一前缀写入表 COMMENT，例如 `relationships` 中每一项都指定 `target_table`、等长非空的 `source_columns` 与 `target_columns`、`cardinality`、`status` 和 `source`。数据库会验证定义结构；该关系作为受治理的语义提示，不会替代真实外键约束，也不会自动改变 JOIN 计划。应用和后续上下文构建器可从 `information_schema.xmysql_table_semantics` 读取可见关系。

确认后的单位和关联由确定性规则使用。未知单位或歧义名称返回可识别错误或明确缺失信息，模型不能自行将猜测变成数据库事实。Schema 或定义变更按目录依赖使相关视图、缓存和上下文失效。Snowflake 语义视图可作为显式元数据组织参考。[R11](https://docs.snowflake.com/en/user-guide/views-semantic/semantic-view-yaml-spec)

### 2 上下文作为查询结果

CONTEXT_AGG 读取已经授权的关系结果、内容块及实际媒体，按任务预算组合字段解释、记录、原文与模态输入。检索负责找材料，执行器随后读取材料。保留 source_ref、位置、版本、处理方法、质量和裁剪范围。

原始记录、解析内容、模型断言和人工确认使用不同 assertion_kind。模型抽取可写入显式派生视图或结果表，不能覆盖来源值。输入不完整时返回缺口，不能在模型回答后才隐藏遗漏。

### 3 模型与适配器

模型目录固定 model_id、版本、能力、输出 Schema 和凭据引用。函数带有外部依赖、确定性、缓存和错误属性；优化器据此决定是否可折叠或复用。批量结果逐项对齐输入并校验类型，技术 UNKNOWN 与 ERROR 默认使严格模型步骤失败，例如调用结果未知、传输失败或响应不符合 Schema。成功返回的证据不足、冲突、需澄清是合法语义状态，不映射为技术 UNKNOWN。

模态适配器按模型能力发送实际图像、音轨、片段或已声明文本表示，由对应 Processor 完成预处理。URL 是否可被提供方读取要验证；只记录哈希不能证明内容已送达，也不能证明模型内部使用了全部像素。[R12](https://huggingface.co/docs/transformers/en/chat_templating_multimodal)

### 4 上层应用回答准确率契约

数据库提供类型化事实、可靠来源、检索与计算能力；最终回答准确率还依赖问题理解、原件质量、模型行为及应用如何生成和展示。系统不能承诺开放问题全部正确。所有正确率均相对于声明的授权来源、冻结数据及参考答案定义，不保证原件本身符合外部现实。

确定性的金额、数量、日期、版本比较和聚合由 SQL 或固定类型规则计算，模型不得重新心算、补单位或从 Top K 推算全量。结果携带值、类型、单位、范围和计算表达式身份；应用可用固定模板展示精确字段，语言模型负责解释，并保留小数精度、空值状态和适用条件。

生成结果返回 answer_status、answer、claims、citations、computed_values、context_manifest_id、quality_assessment 和模型用量。每个重要 claim 关联实际进入上下文的 evidence_id 或确定性计算结果，并声明核验方式。引用可回读、位置正确仅证明出处有效；还须检查证据是否支持该主张、是否遗漏限制或否定条件。该语义判断仍需独立标注评测，不能用“第二个模型通过”当作事实证明。

生成后先校验引用身份、数值及单位、来源版本与权限，再执行声明的主张支持和冲突检查。发现无依据陈述应删除、修正或返回不确定状态；不足材料不强行生成确定结论。quality_assessment 区分 NOT_RUN、RULE_CHECKED、MODEL_ASSESSED 和 HUMAN_VERIFIED，分别附适用项与未覆盖项。ANSWERED 只表示系统按该策略产生回答，不作为真实性担保。

| 内容与核验 | 对外状态 | 支持要求判定 |
| --- | --- | --- |
| 仅 SQL 事实及固定模板，类型 单位 范围等规则通过 | ANSWERED，RULE_CHECKED | 只对已校验确定性内容满足 |
| 自由生成，仅核对引用存在或尚未完成语义支持检查 | UNASSESSED，可作为未核验预览 | 不满足 require_supported_answer |
| 关键主张均完成策略指定支持核验，已声明条件无未决缺口 | ANSWERED，标明 MODEL_ASSESSED 或 HUMAN_VERIFIED | 按该版本策略满足，不宣称事实已被证明 |
| 评估成功返回不足 冲突或需澄清 | 对应语义状态，答案为空或受限说明 | 不满足支持要求，可正常表达拒答 |
| 调用结果未知 传输失败或响应类型不合法 | 严格请求失败并返回技术错误 | 不作为合法拒答或通过核验 |

require_supported_answer 最低检查来源身份、当前权限、实际输入引用、适用的类型化计算值及单位、重要主张的支持关系和已声明问题条件。自由生成必须完成指定语义检查，NOT_RUN、仅引用有效或无法判定不能通过；纯 SQL 事实可以由确定性规则满足，不强制多调用模型。核验策略固定版本并公开适用项。运行时识别的问题条件不等于离线标注的全部真值，模型支持判断也不构成真实性证明。

应用必须保留事实与推断、历史来源、不确定性和拒答状态。若应用再次摘要或改写，应形成新的生成版本、重新进行最终文本核验，并绑定最终文本摘要；不能将旧核验标志附在改变过数字、条件或结论的新文本上。调用方可以不用专用 SDK，但普通 Java Python 客户端也必须能取得这些字段及错误，固定格式展示可直接使用确定性结果。

端到端评测同时报告已回答问题的正确率、可答问题的正确覆盖率、回答覆盖率、应拒答反例的错误肯定率，以及主张支持率、引用有效率和定位正确率。未回答、超时、失败均保留在总问题账目中；不同分母分别公开。最终应用展示文本也纳入抽样或集成验收，不能只评测数据库返回的中间答案。

## 十 同一 SQL 下的读取与驱动契约

### 1 原始快照与派生就绪

复用连接事务和结果游标表达固定读取。跨请求续读时，数据库签发受控结果或大对象句柄，内部保存来源清单与过期时间；这不是要求用户管理的独立会话服务。语义定义与来源版本在同一读取上下文中固定，权限在每次实际访问时重查。

原始快照和实际读取派生结果的快照可以不同，二者通过不可变来源清单绑定。严格等待先固定来源、结束初始事务、等待相应派生结果，再建立新读取快照验证，不在旧快照中等待未来提交可见。PINNED 保留固定范围；CURRENT_GUARDED 检查新增、删除、源值及定义变化，发现变化返回 INPUT_CHANGED。

跨快照等待只用于 autocommit 的独立查询或显式签发的固定来源结果句柄。用户已执行 BEGIN 时，保留原事务的隔离和读己之写语义，不能隐式提交或替换快照；若所需派生值在该事务内不可见，返回 NOT_READY，并由调用方决定提交后再查。同一显式事务中写入新内容后，可读取原始值，但不等待后台事务发布的派生结果变得可见。

LATEST_AT_CAPTURE 是捕获时最新；AT_LEAST_RECEIPT 要求包含指定提交回执；BOUNDED_STALENESS 依据无洞覆盖前沿。水位按能力与范围推进，不能用最大完成序号越过未完成项。详见配套契约，范围、能力、覆盖、预算与近似模式是独立维度。

### 2 已发布代际与可用性

严格读取当前捕获来源时，默认不隐式长时间等待；缺少必要派生值立即 NOT_READY，调用方可显式给出有限等待期限。普通表的事务和隔离语义不变，不把所有 SELECT 改成读取旧代际。

派生查询可通过 SQL 读取选项显式选择最新可见的完整 SERVING 代际，并声明允许的提交落后或时间上界；未设上界须明确接受所选代际的历史来源。返回 generation_id、来源截止点、捕获时变化前沿、落后范围及适用能力。变化前沿无法可靠证明时报告 UNKNOWN，不能通过有界新鲜度要求。没有合格代际时返回 NOT_READY 或 FRESHNESS_REQUIREMENT_UNMET，不悄悄回退更旧结果。

完整代际只对它的固定来源、定义及能力完整，不等于包含后来提交的数据，也不保证模型结论正确。代际结果必须配套该清单中的关系值与内容版本；不能将旧正文拼接当前源行。与普通最新表 JOIN 时按来源修订键匹配，不匹配项按严格覆盖规则报错或显式披露，不能静默漏行。显式事务只读取其快照可见的目录代际；不得隐式切换事务。

在线检索可显式采用“完整已发布代际加新鲜度上界”的配置；正式统计可采用“固定最新来源加完整覆盖”的配置；交互预览可显式允许部分结果。这些是独立策略字段的组合示例，不新增四个互斥模式。历史访问仍需当前有效权限，撤权或强制删除可使旧代际读取失败。

### 3 结果完整性与类型

来源枚举、处理覆盖、检索范围、传输完成和提取质量分别报告。REQUIRE_ALL 下未就绪、处理失败、质量不符或预算不足必须作为驱动能感知的 SQL 错误。ALLOW_PARTIAL 只能显式选择，且附覆盖与失败明细。普通驱动可用同连接的只读状态视图或查询结果 ID 读取元数据，不能依赖自定义协议尾包。

普通 NULL 保持 SQL 语义，派生值另有 value_state。BIGINT、DECIMAL、日期、无时区本地时间及二进制在驱动往返中保持本机类型，转为 JSON 上下文时声明类型与无损编码。流未正常结束，客户端必须感知错误；缺少错误并不能证明分页已经读完，封装的大对象读取需有长度与完整性校验。

### 4 Java Python 端到端验收

用普通 JDBC 驱动与一个公开 MySQL Python 驱动分别完成建表、二进制参数导入、事务提交、源内容读取、派生视图查询、检索、上下文获取、错误处理和删除。SDK 可简化句柄续读，但不得成为访问正确性所必需的业务编排层。

原件大对象先返回固定版本句柄，后续用 SQL 范围读取；句柄绑定来源与当前授权，不能在文件更新时拼接新旧字节。MySQL 长参数协议是可复用入口，但现有实现的缓冲、大小限制、断连清理和驱动行为必须重新验证。[R17](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_send_long_data.html)

## 十一 Agent 与智能执行的边界

Agent 直接使用表结构、查询计划、内容视图、检索和上下文函数。第一目标是让任何客户端都能取得可靠输入，Agent 无额外的数据权限。自然语言规划产生的 SQL 必须经同一 AST、类型、权限和预算检查。

Agent 默认只读，任务声明的读写范围由内核校验；即使连接身份具有更广权限，原件中的指令和模型输出也不能扩大该任务的动作范围。后续写入能力需要独立定义目标表、语句类型和事务边界，不依靠提示词约束代替执行权限。

长任务确有需要时，复用数据库维护作业及结果句柄，增加有界步骤和检查点。状态、计划版本和结果仍在同一目录事务管理，不新建任务数据库、记忆数据库和外部工作流依赖。跨任务经验先作为普通授权表或物化结果；相似问题不能证明结果等价。

模型调用和外部读取作为检查点步骤记录。恢复复用已提交结果；远程调用存在结果未知窗口，不能保证外部效果天然恰好一次。取消与成功通过发布屏障有序裁定，取消不等于上游立即停止计费。相关持久执行原理可参考 DBOS。[R8](https://www.dbos.dev/durable-execution)

Agent 专用语法与通用工具编排不纳入多模态候选版前置条件。任务级共享扫描、轻量学习优化和语义算子组合在稳定 SQL 能力上逐步验证。[R6](https://www.vldb.org/cidrdb/papers/2026/p32-liu.pdf)

### 核心 GenAI 与通用 Agent 的分工

U28 交付只读自然语言 SQL：仅提供授权 Schema 和语义解释，生成的 AST 再经过类型、对象权限、任务动作范围、结果及模型预算校验。默认返回 SQL 和诊断，显式执行模式也只允许受控 SELECT，拒绝多语句、锁定读、文件输出和可产生外部副作用的函数。生成与执行分开留证，不能因模型输出正确语法就认为授权正确。

U29 交付 RAG 便利入口与多轮问答，复用检索、CONTEXT_AGG、显式生成和来源清单；引用定位到实际输入，不建立另一套检索或任务事实库。多轮状态采用同库授权记录，含 conversation_id、turn_no、输入输出、来源和模型版本。轮次唯一键及 CAS 防止并发覆盖，每轮重新鉴权，历史答案不能冒充原始事实；撤权后不能通过旧摘要取回隐藏数据。

U28 U29 属 P2 核心 GenAI，P3 综合追平验收必须覆盖；P4 只增加有界多步 Agent、外部结果未知窗口及长任务恢复。U30 补齐通用文档格式。新增功能沿现有目录、事务和 SQL 执行机制集成，详细功能及验收以追平矩阵 A01 到 A14 记录。

### 2 内部接口契约

最小接口组为 IContentStore、IContentProcessor、IModelProvider 和 IDerivedMaintainer。它们是数据库内部实现边界，不要求开发者逐个调用。

IContentStore 写入并校验不可变对象、打开固定范围、查询长度与回收；成功写入不等于源行已提交。IContentProcessor 接收固定内容值与处理配置，输出规范块、诊断和来源位置。IModelProvider 接收模型版本和有类型的批量输入，逐项返回状态、值及用量。IDerivedMaintainer 复用事务上下文登记维护意图，并在租约、源版本和定义版本有效时发布结果。

所有接口支持 context.Context、取消、预算和访问身份。事务提交由现有权威事务管理器负责，不能由对象后端伪造 Commit。处理器可以替换实现，不决定事实源、索引状态和用户权限。

### 3 最小目录增量

复用表列、视图、索引、权限和提交目录，增加四类内部记录即可表达首期生命周期：大对象版本与引用；派生定义及依赖；处理进度与维护作业；结果句柄与来源清单。模型配置作为受控执行依赖并入目录。规范内容行可存物化视图，向量属于索引或显式派生列，不额外建立用户必须操作的资产、流水线和 Agent 资源体系。

## 十三 安全威胁模型与资源隔离

### 1 信任边界

数据库内核持有事务、目录及授权；解析与解码进程只获得完成指定任务所需的固定内容输入和受限输出通道，不能直接更新目录、读取任意文件或取得数据库管理员凭据。模型提供方是单独的外发边界，按授权域配置允许外发的列、模态、目标和脱敏规则；使用本地模型不自动豁免来源权限检查。

| 威胁入口 | 必须控制 | 验收与诊断 |
| --- | --- | --- |
| 恶意 PDF 图片及媒体 | 白名单、文件签名与结构校验、独立进程、只读输入、超时及内存限制 | 畸形输入只失败对应作业，主 SQL 进程存活 |
| XLSX 压缩炸弹与外链 | 限制解压总量、文件项数、递归层次和单项大小；禁宏及自动外链 | 超限停止；不因压缩后文件小而绕过限额 |
| 路径与远程地址 | 数据库生成内部键，不接受任意文件路径；默认禁止内容触发远程读取 | 路径穿越、重定向和内网探测被拒绝 |
| 文档中的提示注入 | 内容只作数据，模型输出经类型校验；SQL 仍过 AST 权限和预算 | 恶意段落不能触发越权查询或外发 |
| 句柄 缓存与共享去重 | 当前授权重查，缓存分域，内部对象键不暴露 | 撤权后命中缓存仍拒绝；不泄露隐藏计数 |
| 模型外发与费用 | 目标白名单、最小数据输入、并发预留及幂等账目 | 越域请求拒绝；未知结果重试不重复释放预算 |
| 原件与模型输入日志 | 日志仅存诊断引用，证据存储按内容权限和保留期管理 | 日志不含密钥或完整原件，访问留痕 |

远程导入若以后开放，需要单独授权、地址与协议白名单、DNS 解析及连接目标校验、重定向逐跳复核和出口网络限制；首期不提供任意 URL 抓取。文件及 SSRF 防护采用分层控制，不能只依靠扩展名、MIME 或字符串 URL 检查。[R20](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) [R21](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

### 2 执行与存储预算

普通 SQL、内容 IO、解码、解析和模型任务使用独立的并发及内存配额，后台处理不占用前台执行线程等待远程结果。按授权域限制上传暂存字节、已提交 LOB、派生产物、delta、活跃句柄和保留代际。提交时已持久化原件必须预留容量；不能先确认成功，再因配额不足删除原件。

队列有上限并持久化，耗尽时明确拒绝新处理需求或背压，不能无限堆积内存。维护积压可使新派生查询 NOT_READY，原始 SQL 继续按其资源配额运行。取消与进程终止后记录最后已提交边界；被隔离进程只能产生待验证输出，不能自行发布结果。

P0 固定资源测量方法，P1 验证文件解析隔离与恢复，P2 增加模型外发、预算和缓存负例，P3 在音视频及 delta 合并并发下复测普通 SQL 的 P95。资源和安全是各阶段退出项，不推迟到最后统一补做。

## 十四 阶段计划与工作包

### 1 交付阶段

| 阶段 | 交付目标 | 退出条件 | 估算与决策 |
| --- | --- | --- | --- |
| P0 内核基线 | 固定构建、事务恢复、协议内存和存储试验 | 明确阻塞缺陷与证据，冻结 v1 契约 | 建议两周调查时间盒；未通过则继续修复，不自动进入 P1 |

| P3 多模态候选版 | 音频视频、跨模态、不变索引段与持久 delta | 四类模态、更新恢复、安全与 PG 对照通过 | 拆分 B C 索引检查点，不要求可变事务图 |

资源假设仍为两名全职 Go 与内核工程师，以及 AI 与测试合计至少一个全职当量；不假设三人可以把所有工作包完全并行。前版 P0 到 P3 的 14 到 22 周、全路线 20 到 32 周均不能作为生产交付周期；评审提出的更长周期同样未经过本仓库工作量验证。本版暂不替换成另一个看似精确的总周数。

P0 的第 1 到 2 工作日固定环境、工作区快照及驱动；第 3 到 5 日验证提交、回滚、崩溃恢复与来源目录；第 6 到 8 日完成有界 LOB IO、描述符编码和维护发布的最小技术试验；第 9 到 10 日汇总缺陷、吞吐内存数据及任务估算。该时间盒用于发现差距，不承诺在两周内修完全部内核问题。

P0 交付三点人周估算、人员与技能分配、依赖关键路径、外部库选型及许可证记录、风险准备金，并给出 P1 的可审查里程碑；每阶段完成后用实测速度重算后续区间。研究预览、多模态候选版和生产就绪分别验收。生产还需长期混合负载、容量上限、升级回退、安全及备份恢复演练，按目标负载另立门槛与排期，不从 P3 完成直接推定生产可用。

多模态范围保持不变，先限制支持格式与容器、文件大小和并发，而不是把产品转为某一行业。优先自主实现内容与事务契约、派生发布及 SQL 优化；HNSW 算法、解析器、OCR 和模型复用成熟实现并受内部接口约束。首期退出条件不依赖自研模型、可变图、专用 Agent 语法或分布式对象后端。

## 十五 验收 对照与发布

### 1 数据集与契约

准备至少两个授权域、1000 个通用内容对象，覆盖 PDF、图片、XLSX、音频、视频与损坏、空白、混合页、超限、更新删除等反例。至少 300 个独立标注问题，其中 RAG 至少 200 题并含 40 道反例，SQL 至少 100 题并含 20 道反例；按原件及修订族分割校准与验收集，防止同源不同块或版本泄漏。

配套契约在前版 42 项基础上增加编码、状态转换、代际、新鲜度、持久增量及安全负例，共 90 项，逐项标明适用阶段。阶段退出要求该阶段及前置阶段的适用确定性场景全部通过；P4 通用多步 Agent 不阻塞 P3 多模态候选版，但核心只读自然语言 SQL 和多轮问答必须纳入 P3 综合验收。P1 先具备未就绪明确报错，P2 再交付跨快照等待、水位和部分覆盖。不能用模型分数或演示替代。原始数据和模型结果均绑定版本、参数及可复查输入。

### 2 对照 PostgreSQL 加 pgvector

B0 是 PostgreSQL 加 pgvector，评估精确与 ANN 距离检索。B1 在相同原件、解析器、模型和质量目标上，组合 PostgreSQL 的全文、大对象及应用维护代码，完成相同多模态任务。公开组成和版本，不能通过省略对方可用功能制造优势。

| 项目 | 固定条件 | 报告内容 |
| --- | --- | --- |
| 向量效率 | 同向量、距离、过滤、召回目标、硬件与缓存 | P50 P95、吞吐、CPU、内存及索引大小 |
| 多模态质量 | 同原始内容、处理器、编码器和问题集 | 片段召回、位置正确率、语义判断及缺失披露 |
| 更新恢复 | 同修改序列、故障点和完整性要求 | 原件与索引可见性、恢复耗时、维护空洞 |
| 开发运维 | 同导入 查询 更新 删除与上下文目标 | 客户端代码、同步逻辑、独立组件和诊断步骤 |

向量基准从一万、十万逐级扩大，百万级在容量阶段验证。初始 ANN Recall at 10 目标为至少 0.95，按过滤比例分项；真值来自精确计算。语义 F1 建议起点 0.85，仅用于明确定义的分类任务；检索相关性和回答正确率使用后述独立指标，按任务和模态校准并报告区间。普通 SQL 混合负载 P95 增幅建议不超过 10%，配置在 P0 冻结。所有数字目前均未实测。

“超越 pgvector”的产品门槛为多模态候选版完整覆盖第一章目标，普通客户端无需自行拼装数据同步与检索库。性能领先只在具体报告支持的条件下表述，不能从产品完整度推出吞吐领先。

### 3 检索与上层回答的分层指标

| 层次 | 指标与口径 | 真值及边界 |
| --- | --- | --- |
| 内容处理 | OCR、表格结构、精确类型和定位正确率 | 独立原件标注；运行 READY 不等于识别正确 |
| ANN 算法 | ANN Recall at K，对比相同向量的精确 Top K | 过滤范围及距离固定，候选不足按有效 K；空范围单列，不作为满分 |
| 证据召回 | Evidence Recall at K 与完整证据组命中率 | 每个必要组命中任一合法替代证据算覆盖；多组需同时满足 |
| 排序质量 | Precision at K、nDCG at K | 独立相关性等级；缺席位置不当作相关，重复证据不重复得分 |
| 上下文 | 必要表头、条件和证据组的输入保留率 | 对最终实际模型输入检查，包含截断、补全及模态损失 |
| 回答与引用 | 结论正确、主张支持、引用有效及定位正确分别统计 | 冻结参考答案、确定性值与人工复核；引用有效不等于主张受支持 |
| 可用性与拒答 | 回答覆盖、正确覆盖、反例错误肯定、超时与失败比例 | 固定全部问题账目，公开各分母，拒答不能消失在统计之外 |

同一查询中选择材料、融合、重排和生成的版本与预算固定。先在校准集冻结评测定义、有效 K、等距处理、相关性分级、阈值和拒答规则，再在留出集一次性验收。切换模型、解析或检索配置需新策略版本及相应回归。宏观指标按问题类型和模态分层报告，展示样本数与置信区间，不以整体均值掩盖局部退化。

正确覆盖率的分母为标注可答问题数，分子为其中正确回答数；已回答正确率的分母为实际给出实质答案的问题数，分子为正确答案数；回答覆盖率为给出实质答案数除以全部合法测试请求数。错误肯定率在应拒答反例中计算。分母为零报告不适用；系统故障作为故障，不伪装为合理拒答。检索相关性目标在 P2 的校准后冻结，当前不承诺通用准确率或未实测的收益。

### 4 确定性门槛与测量口径

| 类别 | 确定性门槛或待校准目标 | 测量证据 |
| --- | --- | --- |
| 内容与事务 | 已确认提交丢失、回滚内容误见、过时发布、跨域越权均为 0 次 | 声明故障点、重启次数、并发序列和检查总数；不是无限负载下的数学保证 |
| 字节与类型 | 验收集中原件哈希及精确类型往返全部通过 | 原件逐字节摘要、BIGINT DECIMAL 时间与二进制边界值 |
| 派生维护 | 无洞前沿、失败可见；不承诺未定义的固定延迟 | 提交到各能力 READY 的 P50 P95 P99、最老积压和输入字节 |
| 代际发布 | 不完整代际发布、混配来源和无声明过期均为 0 次 | 指针事务故障注入、更新竞态及新鲜度反例 |
| 检索与质量 | ANN Recall at 10 建议至少 0.95；语义与提取另设标注集 | 按过滤比例、模态、delta 比例和置信区间分项 |
| 前台隔离 | 普通 SQL P95 增幅建议不超过 10% | 相同混合负载与缓存条件，P0 冻结预算配置后比较 |
| 应用复杂度 | 统计同步代码、组件及恢复步骤，不预设减少 50% | 同任务最小可用客户端与维护逻辑，计数规则随报告公开 |

维护延迟 SLA 需要同时声明内容大小分布、模态、并发、模型部署及资源预算；P0 先定方法，P1 P2 用负载曲线给出容量区间。到期返回 NOT_READY 不是履行 SLA 的替代证明。吞吐、质量、稳定性与开发成本分别报告，不能用单一综合分掩盖失败门槛。

### 5 MySQL AI 核心功能对照

MySQL AI 核心清单为追平矩阵 A01 到 A14 排除 A06 的 13 项，C58 到 C66 为补充契约；A06 ANN 属候选版独立增强门槛，HeatWave 自动索引为后续。实际状态逐项关联代码、命令、测试数和原始日志；“已有协议基础”不能推导为“已支持 AI”。自然语言 SQL 用独立标注集检验实际结果等价性，覆盖过滤、JOIN、聚合、NULL、排序和时间，歧义澄清或拒答，不能只看可执行性。完整流程从同一批文件导入，到处理进度、检索、生成、引用回读，再到更新删除及中断恢复，均通过普通 SQL 客户端验证。P3 只有在核心清单和多模态清单均通过后，才可分别声明相应范围的功能完成。

### 6 现有 MySQL 能力的分支发布门槛

每阶段保存旧功能的固定用例、已验证状态和已知偏差，随后在新增能力关闭及开启两种配置下回归。普通 SQL 的结果与列类型、errno 和 SQLSTATE、警告、事务边界、权限及已有元数据按冻结口径比较。涉及无 ORDER BY 的结果采用合法等价比较，不能用偶然输出顺序判定回归，也不能忽略重复行、NULL、精度或明确排序。基线已有失败保留为未通过，修复另列；新失败不可改作“不支持”或静默跳过。

先以普通负载测基础成本，再加入解析、解码、模型和索引合并并发，按资源配额核对旧查询的延迟、取消与错误。AI 不可用时，新请求应有可识别状态，既有非 AI 功能继续运行。MySQL 兼容旧能力、核心 GenAI、RAG 质量及多模态目标分别验收，任一新能力演示不能替代旧能力回归。

### 7 发布与回退

目录迁移采用增量和兼容读者，新能力默认关闭。先原件与派生视图，再检索与上下文，之后音视频和 ANN。每阶段通过相关事务、权限和恢复测试后开放小范围只读负载。

回退可关闭新的派生维护或模型计算，保留原始列、来源和诊断记录，索引切回已验证版本。新目录格式不默认允许旧二进制直接打开；使用兼容读者或验证备份恢复。删除保护、当前权限和来源核验不能因回退失效。
