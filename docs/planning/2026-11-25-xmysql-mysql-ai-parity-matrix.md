# XMySQL 对标 MySQL AI 的追平矩阵与执行入口

版本 0.3  2026 年 11 月 25 日

目标是实现并验证 MySQL AI 的核心文档与 GenAI 使用闭环，同时保留 XMySQL 原生多模态关系数据库方向。本矩阵补充[内核计划](2026-11-25-xmysql-multimodal-ai-agent-plan.md)与[数据契约](2026-11-25-xmysql-data-access-contract.md)，不代表已经追平。每项必须同时记录实现位置、执行命令、原始结果与缺口；仅有函数名、示例或模型演示不能判定通过。

## 一 固定比较对象

主要功能基线固定为 MySQL AI 26.10 官方手册，访问日期为 2026 年 11 月 25 日；实际对照运行还必须记录二进制构建号、平台、模型、解析器、数据与配置。未获得可运行的对照环境时，只能完成文档能力核对，不能报告实测性能追平。

MySQL AI 的官方 GenAI 能力已经包含文档处理、嵌入、RAG、摘要及对话等 SQL 使用方式，不能将这些本身宣传为 XMySQL 独有创新。[GenAI 总览](https://dev.mysql.com/doc/mysql-ai/26.10/en/mys-ai-genai-overview.html)

HeatWave 单列参考线 H，不混入 MySQL AI 26.10 的实现结论。其手册说明自 MySQL 9.5.0 起可自动创建 HNSW 等向量索引；这是对 ANN 与自动索引的独立对照，不能据此推定 MySQL AI 26.10 具有完全相同的自动索引实现。[自动向量索引](https://dev.mysql.com/doc/heatwave/en/mys-hw-genai-vector-index-creation.html)

首轮“核心功能追平”不包含完整 AutoML 训练、模型解释、漂移检测，以及 HeatWave 分布式加速、规模和性能。原始图片、音频、视频及跨模态对齐仍属于 XMySQL 的既定产品目标；核心文档能力完成不意味着这些目标已经完成。

## 二 状态与证据规则

状态统一为：待实现、已有基础待验证、已验证、受阻、后续范围。源码中没有找到原生入口时记为“待实现（静态检索）”，不把文本检索当成不存在任何相关代码的数学证明。只有本版本、当前工作区快照的新鲜运行证据可将状态提升为已验证。

一条证据记录至少包含功能 ID、源码快照摘要、命令、退出码、测试数、数据摘要、环境、日志位置及不覆盖的边界。单元测试、真实模型测试、SQL 端到端、故障恢复及对照性能分层记录，互不替代。模型桩只可验证协议和失败路径，不用于声明 OCR、回答或抽取质量。

## 四 第一轮可运行闭环及顺序

E0 固定环境与代码快照，构建二进制，运行协议、复制字节、事务、权限及恢复的聚焦检查。工作区存在用户既有修改，验证必须在保留这些修改的隔离快照中进行；既有测试数据及正在使用的数据库不作为可清理目录。环境或构建失败必须先分类，不能直接宣称内核基线通过。

E1 先做普通客户端写 CONTENT、提交、原件范围读取与删除的纵向路径，再加入持久维护意图、规范内容视图和处理器。覆盖 TXT、数字 PDF、扫描 PDF 后扩到 HTML 与 Office 文档；这只是实现顺序，A01 全格式未通过之前不能宣称文档导入追平。旧 DOC/PPT 转换需受限进程及单独格式测试，不能与宏或外链自动执行绑定。

E2 使用已有模型完成实际嵌入、精确检索、上下文、摘要、批量抽取和回答引用。RAG 便利入口复用已有 SQL 算子和模型目录，不建立另一套编排事实源；其输出包含 answer、citations、coverage、source_manifest 和 model_usage。检索与生成预算分别预留，无命中、不足证据与模型未知区别处理。调用方可以只检索上下文，不能强迫所有 SELECT 付费推理。

E3 补齐只读自然语言 SQL 和多轮问答，再完成不可变 ANN 段与持久 delta。自然语言 SQL 默认先返回 SQL 文本及诊断，执行模式仅接受当前任务允许的 SELECT；锁定读、INTO OUTFILE、任意函数外发及多语句等副作用入口须由 AST 策略明确拒绝。多轮记录含 conversation_id、turn_no、输入、输出、来源清单、模型版本和授权身份；同一会话轮次以唯一键及 CAS 串行发布，重试不重复追加。每轮重新校验当前授权，历史引用失效要披露并重新检索，不能靠旧摘要绕过撤权。

E4 按相同文件与问题集执行双方对照。MySQL AI 26.10 核心集合为 A01 到 A14 中排除 A06 的 13 项，全部满足各自验收，且与基础契约无冲突。A06 的 ANN 仍是 XMySQL 多模态候选版的独立门槛，自动索引另列后续，不能用手动 ANN 通过宣称追平 HeatWave 自动索引。没有双方同条件实测时，报告“本项目功能通过、对照未运行”，不能写成性能追平。多模态音视频、Agent 多步恢复、AutoML 和分布式加速分别沿原阶段与后续范围推进。

U28 为只读自然语言 SQL；U29 为 RAG 便利入口及同库多轮状态；U30 为通用文档格式补齐。U28 U29 U30 属核心 GenAI 范围，不再与 P4 通用 Agent 平台混为一谈。已有 U01 到 U27 的存储、派生、检索和安全依赖仍然有效。

## 五 对照方法与当前执行记录

固定两套授权域、同一批文件、同一批独立标注问题和拒答反例。双方使用同模型与解析器的可比部分单列；无法采用相同组件时报告差异，不能将模型差异归因于数据库。记录单文件处理、批量吞吐、端到端 P50 P95 P99、并发、CPU、内存、存储及模型用量；文档大小、页数、模态、delta 比例和缓存条件与结果一并保存。

功能用例逐项判定，质量按标注集和置信区间报告，可靠性检查并发更新、回滚、删除、重启和处理中断，性能采用固定硬件与规模。测试数为零、只编译测试二进制、只使用模型桩或缺少真正的来源读取，都不能提升对应状态为已验证。

自然语言 SQL 在独立问题集中保留至少 100 道结构化查询及歧义或不可答问题，其中至少 20 道需要澄清、拒答或权限拒绝，覆盖过滤、JOIN、聚合、NULL、重复值、排序及时间语义。人工编写并复核参考 SQL，固定数据后对比实际结果等价性，不能只比较 SQL 字符串、可执行性或让同一生成模型自评。分别报告执行正确率、合理拒答、错误自信回答与超时比例；正确率分母和质量阈值在验收前冻结，不因失败删除样例。U28 负责实现与子集，U20 负责独立留出集对照。

## 六 检索与上层回答质量的补充门槛

A07 与 A08 增加检索、重排、上下文及最终答案的分层评测，落入 U12 U15 U16 U20 U29；具体契约见主计划第八 九 十五章和 C67 到 C84。原 30 个工作包承载这些职责，不新建外部检索平台。检索策略、模型与缓存版本固定，普通 SQL 的精确性和 ORDER BY 不因语义处理而改变。

ANN Recall 只评价近邻算法，Evidence Recall 与完整必要证据组衡量材料覆盖，Precision 与 nDCG 衡量排序；回答正确率、正确覆盖率、回答覆盖率和反例错误肯定率必须一起报告。数值与聚合来自 SQL，关键主张关联实际证据；应用二次生成要重新核验最终文本。引用存在不证明支持结论，模型核验不等于事实证明；公开问题的准确率不能承诺百分之百。

至少 200 道 RAG 题及其中 40 道反例，与至少 100 道 SQL 题及其中 20 道反例组成既定问题集，按原件修订族切分校准与验收。P2 按适用模态交付核心质量链，P3 增加 ANN 和音视频消融及综合对照。当前仍待实现，既有基线通过数不增加。

## 七 开发分支的现有能力保留门槛

本分支以保持当前 XMySQL 的 MySQL 兼容能力为前提增量增加 AI 和多模态，不形成删减 SQL 的专用 RAG 数据库。U01 固定现有通过、待验证、已失败、未支持及未覆盖状态，U20 对新能力关闭、开启和混合负载执行旧功能集回归；新增功能不能替代旧功能验收。具体范围及 C85 到 C90 见主计划第一章与配套契约。

旧协议、类型、语义、事务、权限、元数据、备份和复制按实际支持范围保留，必要缺陷修复明确影响与证据。普通 SQL 不隐式调用 AI，模型离线不阻断基础服务。既有测试的新回归阻止发布，已知失败保留且不计为已支持；旧 XMySQL 回归与对上游 MySQL 的差分兼容分别报告。
